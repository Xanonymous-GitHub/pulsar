# AGENTS.md

This project was generated by `esp-generate` for Espressif MCUs.

## Project-specific notes

- Target chip: `esp32c5`; keep dependencies, HAL features, and examples compatible with this chip.
- Check the `generator parameters:` comments in `src/bin/main.rs` before changing code that depends on selected generation options.
- This is a `#![no_std]` / `#![no_main]` project. Avoid `std`; use `core` and embedded-friendly crates.
- `alloc` is not enabled. Avoid heap-backed types such as `Vec`, `String`, `Box`, and boxed futures unless you add and initialize an allocator.
- `.cargo/config.toml` contains the generated target, runner, build flags, and `[env]` defaults. Espressif crates expose additional configuration through environment variables; use `esp-config` to inspect/set those options. The linked "Additional configuration" sections for the enabled Espressif crates document crate-specific variables; keep project-specific defaults in `[env]` instead of hard-coding them in source.
- Logging uses `log`/`esp-println`; the default filter is `ESP_LOG=info` in `.cargo/config.toml` and can be overridden from the environment.
- `cargo run` uses `espflash` as configured in `.cargo/config.toml`. This path flashes through the board's serial/USB bootloader connection.
- If flashing fails, check bootloader mode, serial-port permissions, the selected port when multiple boards are connected, and that the `--chip` in `.cargo/config.toml` matches the target.

## Project learnings

- The package/bin is named `pulsar`. The directory was renamed from `esp32-c5`; `esp32-c5` is stale and should not reappear.
- `.cargo/config.toml` must exist and set `[build] target = "riscv32imac-unknown-none-elf"`. Without it cargo builds for the macOS host and fails in `esp-hal`'s build script and with `invalid Mach-O section specifier` in `esp32c5`.
- `eim_config.toml` is Espressif Installation Manager output (machine-specific). It is gitignored and not used by the Rust build.
- A heap IS enabled now (`esp-alloc`, `HEAP_SIZE` in `main.rs`) because `esp-radio`/`esp-rtos` need it; the generated "alloc is not enabled" note above is outdated. Still avoid needless allocation.
- `main` is `async` (`#[esp_hal::main]` + `esp-rtos` `embassy` feature). `esp_rtos::start(...)` must run before any radio is created; use `embassy_time` instead of busy-wait delays.
- `esp-radio` needs `opt-level = 3`; `Cargo.toml` overrides it per package for dev and release (the project default is `s`/`z`). Do not remove the overrides.
- `partitions.csv` adds an `encrypted` `secrets` partition for `src/secret_store.rs` (must use the `undefined` subtype); the runner passes it to espflash, so run `cargo run` from the project root.
- `esp-bootloader-esp-idf` 0.6.0 swaps the partition `encrypted`/`readonly` flag bits (espflash/ESP-IDF: bit 0 = encrypted); `secret_store` reads raw flags and uses `esp-storage` offsets directly. Do not switch to `as_flash_region` (gives `WriteProtected` / plain writes).
- Without flash encryption the secret store refuses to open; the off-by-default `insecure-dev-store` feature stores plain text for testing only. Never run eFuse commands from automation, and never commit credentials.
- Wi-Fi credentials come from the shell env at build time (`PULSAR_WIFI_SSID`, `PULSAR_WIFI_PASSWORD`, read by `option_env!` in `src/wifi.rs`) and are kept in secret-store slot 0; unset both to reuse the stored ones.
- `esp-radio` 1.0.0-beta.1: `StationConfig` lives at `esp_radio::wifi::sta::StationConfig`, and `WifiController::is_connected` is `unstable`-gated (use `rssi()` returning `NotConnected` instead).
- The display is an SSD1306 128x64 on I2C (XIAO D4 = SDA = GPIO23, D5 = SCL = GPIO24); the user LED is GPIO27.
